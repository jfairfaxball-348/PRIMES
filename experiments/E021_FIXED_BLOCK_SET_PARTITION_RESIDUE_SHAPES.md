## 1. Exact combinatorial object and independent evaluator semantics

For n>=0 and k in {3,4}, let `S(n,k)` be the number of partitions of the labelled set {1,...,n} into exactly k **nonempty, unlabelled** blocks. By definition S(n,k)=0 for n<k; S(0,0)=1 only as a synthetic recurrence reference. The underlying objects are *unordered set partitions*, not generator words, linear tile compositions, permutation products, polynomial residue orbits, graph forests, factorisations of n±1, or prime events.

Freeze exactly the two adjacent small block counts 3 and 4. The complete exact counting formulas for n>=1 are

- `6*S(n,3) = 3^n - 3*2^n + 3`;
- `24*S(n,4) = 4^n - 4*3^n + 6*2^n - 4`.

Their source-independent meaning is that the alternating sums count surjections onto k **labelled** boxes and division by k! forgets box names. No other block count, offset, partial-block weighting, partition lattice statistic, recurrence coefficient, alternative exponent, new modulus, group action or feature family is permitted. For bounded synthetic verification only, `S(n,k)=k*S(n-1,k)+S(n-1,k-1)`, with `S(0,0)=1` and all `S(n,k)=0` when k<0 or k>n, supplies an independent exact reference.

For each integer anchor x>=1, fix the **one-point extension modulus** `m=x+1`. This convention treats the x labelled points as a subset of the canonical (x+1)-point extension and is frozen before observing labels; unlike reducing an exponent-x count modulo x, it does not identify the block-counting modulus with the cardinality counted. Define `r3(x)=S(x,3) mod m` and `r4(x)=S(x,4) mod m` as canonical integers in [0,m). This x+1 choice is a first-principles extension convention, not an empirical shift, an E007 neighbour factorisation, an E020 endpoint retune or a reported prime law.

**Production algorithm, no huge powers or factorial:** for k=3,4 let d=k!, let `N_k(x)=sum_(j=0)^k (-1)^(k-j)*C(k,j)*j^x`, with 0^x=0 for x>=1. Because the exact N_k is divisible by d, this gives precisely `S(x,k) mod m` without a modular inverse or illegal division. Complexity is O(log x) fixed-small-base modular multiplications per anchor, independent of any prime oracle; synthetic small n may instead enumerate partitions/recurrence. No full `j^x`, high-anchor x-step recurrence, label-conditional helper, factorisation of x or x+1, floating arithmetic or per-anchor primality check is allowed.
